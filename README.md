# BOS.pro

**Система управляемого выполнения задач с проверяемым результатом.**

Репозиторий: [BOS-Pro_30.10.2026](https://github.com/dimitry8st-prog/BOS-Pro_30.10.2026).
Статус: технический прототип. В `main` объединены PR №1 (учебный сценарий и
файловое хранилище) и [PR №2](https://github.com/dimitry8st-prog/BOS-Pro_30.10.2026/pull/2)
(PostgreSQL RunStore, миграции 001–003, RLS и изоляция workspace).
Ветка `local-session-api` добавляет локальный серверный обработчик с доверенной
сессией. Публичного входа, HTTP-сервера и готового пользовательского приложения нет.

BOS.pro помогает поставить задачу, выбрать проверяемый сценарий, получить результат
от ИИ и инструментов, проверить его и сохранить историю выполнения. Человек видит
исходные данные, результат, замечания, затраты и действия, требующие подтверждения.

Первый сценарий: подготовка публикации из проверенных источников с сохранением
черновика, проверкой ссылок и отдельным подтверждением публикации. Дальнейшие
направления — маркетинговые эксперименты и фоновые задачи создания видео.

## Первый результат разработки

Пользователь создаёт задачу и получает сохранённый черновик публикации, список
источников и отчёт проверки. Отдельный запуск имеет собственный статус, бюджет
и журнал. Наличие черновика не означает, что он опубликован.

## Учебный прогон v0.1

Команды выполняются из корня репозитория. Среда, в которой собран этот этап: Node.js `24.12.0`. Точные версии TypeScript и `@types/node` зафиксированы в `package-lock.json`.

```text
npm ci
npm run check
npm test
npm run scenario:fixture
```

`npm run scenario:fixture` записывает учебный запуск в каталог `var/dev-store`. Это локальное хранилище `development-only`: файлы переживают перезапуск процесса на этой машине. Это не PostgreSQL, не Supabase и не сервер.

Код выхода `0` у команды `run` означает, что запуск сохранён со статусом `succeeded`. Одобрение текста смотрят в `verification`, публикацию — в `publication.status`. На этом этапе публикация остаётся `not_published`.

Повтор той же команды с тем же ключом возвращает тот же `run_id`. `FixtureProvider` не вызывает модель и не проверяет URL по сети. Прохождение теста не является проверкой реальной модели, живого сайта, RLS или production.

## Проверка после редактирования

Любое изменение текста создаёт новую версию без привязок утверждений предыдущей
версии. Пока новые привязки не проверены, `verification=fail` и
`quality_gate=blocked`. Повторная запись того же текста не создаёт ещё одну версию
и не меняет её статус. Исходная версия и её отчёт сохраняются.
Это ограничение учебного сценария: автоматическая повторная проверка фактов пока
не реализована, поэтому ручная правка сама по себе не получает `pass`.

## PostgreSQL

Серверный адаптер `PostgresStore` хранит запуски в PostgreSQL. Файловый режим
`npm run scenario:fixture` не требует базы и работает как прежде. Границы этапа —
[POSTGRES_STAGE.md](docs/POSTGRES_STAGE.md). Контракт будущего серверного доступа —
[SERVER_ACCESS_CONTRACT_V0_1.md](docs/SERVER_ACCESS_CONTRACT_V0_1.md).

Проверка:

```text
npm run check
npm test
npm run test:postgres
```

Без `BOS_TEST_DATABASE_URL` последний тест идёт на PGlite — это отдельно от TCP.
Для обычного PostgreSQL укажите административный URL пустой одноразовой базы на
`127.0.0.1`. Тест создаёт учебные login-роли и подключается ими. Повтор на уже
наполненной базе не запускается: тест не удаляет данные.

Учебный сценарий в отдельной базе `bos_educational`: `npm run scenario:postgres`.
Пароли только в окружении; `BOS_EDUCATIONAL_DATABASE=1`. Повтор той же команды на
той же базе переиспользует LOGIN без `ALTER ROLE` и возвращает тот же запуск.
Команды — в [POSTGRES_STAGE.md](docs/POSTGRES_STAGE.md). `FixtureProvider`
остаётся, пока не выбраны endpoint и бюджет.

## Локальный серверный слой

`LocalSessions` выдаёт непрозрачную сессию только из доверенного серверного кода.
`LocalTaskApi.dispatch(token, request)` выполняет четыре операции: `create_task`,
`prepare_draft`, `read_result`, `revise_draft`. Workspace берётся из сессии,
DB LOGIN должен совпадать с пользователем. Запись для `viewer` запрещена.
Сессии истекают, отзываются и не переживают перезапуск процесса.

Это обработчик внутри процесса без HTTP-порта, паролей пользователей и публичного
входа. Он не принимает `user_id`, роль или строку подключения из JSON. Пулы
соединений задаёт сервер. Миграции и выдача membership остаются административными
операциями вне API; автоматической публикации нет.

Проверки сессий включены в `npm test`; проверки четырёх операций с Alice, Bob,
editor и viewer — в `npm run test:postgres`, на PGlite или native PostgreSQL.
Контракт и пример: [LOCAL_SERVER_STAGE.md](docs/LOCAL_SERVER_STAGE.md).
