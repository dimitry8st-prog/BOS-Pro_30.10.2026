# BOS.pro

**Система управляемого выполнения задач с проверяемым результатом.**

Репозиторий: [BOS-Pro_30.10.2026](https://github.com/dimitry8st-prog/BOS-Pro_30.10.2026).
Статус: черновик концепции от 30 октября 2026 года. На ветке `scenario-contract-v0.1` добавлен учебный контракт v0.1 и локальный прогон `FixtureProvider`. Это не готовое приложение и не решение, утверждённое владельцем.

BOS.pro помогает поставить задачу, выбрать проверяемый сценарий, получить результат
от ИИ и инструментов, проверить его и сохранить историю выполнения. Человек видит
исходные данные, результат, замечания, затраты и действия, требующие подтверждения.

Первый сценарий: подготовка публикации из проверенных источников с сохранением
черновика, проверкой ссылок и отдельным подтверждением публикации. Дальнейшие
направления — маркетинговые эксперименты и фоновые задачи создания видео.

## Первый результат разработки

Пользователь создаёт задачу и получает сохранённый черновик публикации, список
источников и отчёт проверки. Отдельный запуск имеет собственный статус, бюджет
и журнал. Наличие черновика не означает, что он опубликован.

## Учебный прогон v0.1

Команды выполняются из корня репозитория. Среда, в которой собран этот этап: Node.js `24.12.0`. Точные версии TypeScript и `@types/node` зафиксированы в `package-lock.json`.

```text
npm ci
npm run check
npm test
npm run scenario:fixture
```

`npm run scenario:fixture` записывает учебный запуск в каталог `var/dev-store`. Это локальное хранилище `development-only`: файлы переживают перезапуск процесса на этой машине. Это не PostgreSQL, не Supabase и не сервер.

Код выхода `0` у команды `run` означает, что запуск сохранён со статусом `succeeded`. Одобрение текста смотрят в `verification`, публикацию — в `publication.status`. На этом этапе публикация остаётся `not_published`.

Повтор той же команды с тем же ключом возвращает тот же `run_id`. `FixtureProvider` не вызывает модель и не проверяет URL по сети. Прохождение теста не является проверкой реальной модели, живого сайта, RLS или production.

Старт запланирован на **31 октября 2026 года**. Первая задача — закрепить входы,

## Проверка после редактирования

Любое изменение текста создаёт новую версию без привязок утверждений предыдущей
версии. Пока новые привязки не проверены, `verification=fail` и
`quality_gate=blocked`. Повторная запись того же текста не создаёт ещё одну версию
и не меняет её статус. Исходная версия и её отчёт сохраняются.
Это ограничение учебного сценария: автоматическая повторная проверка фактов пока
не реализована, поэтому ручная правка сама по себе не получает `pass`.

## PostgreSQL

Добавлен серверный адаптер `PostgresStore`, миграции, RLS и интеграционный тест.
Команды и границы этапа — [POSTGRES_STAGE.md](docs/POSTGRES_STAGE.md).
Файловый CLI сохраняет прежнее поведение. Проверка:

```text
npm run check
npm test
npm run test:postgres
```

Для локального PostgreSQL `16.10` на отдельном кластере `127.0.0.1:54329` укажите пустую базу и выполните `npm run test:postgres`. Пример: `postgres://postgres@127.0.0.1:54329/bos_pr3_test`. Повтор на уже наполненной базе не запускается: тест не удаляет данные. `FixtureProvider` остаётся, пока не выбраны endpoint и бюджет.
