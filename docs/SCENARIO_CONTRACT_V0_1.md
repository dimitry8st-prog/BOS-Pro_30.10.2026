# Контракт сценария v0.1 — подготовка черновика

Статус: предложение исполнителя для учебного этапа. Это не решение, утверждённое владельцем.
Дата: 31 октября 2026 года.
Исходная точка `main`: `9b46b603d9304e331ab51bf9f7fdecc4bc11ea19`. На момент чтения новых коммитов поверх этой точки не было.
Ветка реализации: `scenario-contract-v0.1`.

Документ конкретизирует первый сценарий «подготовка публикации с источниками и отчётом проверки» для локального учебного прогона. Campaign и experiment для этого сценария не используются.

## Что уже было в черновиках и что здесь предложено

Черновики `docs/*_DRAFT.md` задают общую модель. Ниже — предлагаемые уточнения. Они не отменяют черновики и не объявлены принятыми.

| Тема | В черновиках | Предложение v0.1 |
| --- | --- | --- |
| `waiting_approval` | Состояние запуска в модели данных | Состояние остаётся в перечислении для будущего внешнего действия. Этот сценарий в него не входит и завершается черновиком |
| `succeeded` | Завершение запуска | Результат и отчёт сохранены. Одобрение текста и публикация учитываются отдельно |
| Качество | Отдельный отчёт проверки | `verification`: `pass`, `fail` или `needs_review`. `fail` и `needs_review` блокируют внешнее действие и не меняют сами по себе `succeeded` на `failed` |
| Ссылки | В оценке продукта ссылки доступны для проверки | Учебный fixture получает `not_checked`. Живая проверка URL этим этапом не выполняется |
| Размещение и бюджет | План сборки просит выбрать их до реализации | Решения из раздела «ещё не приняты» остаются открытыми и не блокируют учебный контракт |
| Доступ | Сервер, membership, RLS | На этом этапе не реализованы. Поле `access_check` равно `not_performed` |

## Класс системы на этом шаге

Подготовка рекомендаций и черновиков. Права внешней публикации отсутствуют. Обработчик внешней публикации отсутствует: запрос публикации отклоняется кодом `publication_handler_absent`, `publication.status` остаётся `not_published`.

Владелец результата и решений: Дмитрий. Этот файл фиксирует предложение реализации.

## Поток

Проверенный контракт → фиксированный исполнитель `prepare_draft` → `FixtureProvider` → детерминированные проверки → неизменяемая версия результата → журнал.

`FixtureProvider` читает только текст, уже лежащий во входе, после того как исполнитель сверил его с каталогом `fixtures/`. Источник не выбирает путь сохранения и не получает команды, сеть или секреты. Вариант поставщика задаёт вызывающий код или флаг CLI `--provider`, а не текст источника. Поле `provider` внутри JSON — неизвестное поле и отклоняется.

Результаты поставщика проверяются как недоверенные данные. Подсказка внутри текста источника не меняет обработчики, права, назначение и бюджет.

Повторов учебного шага поставщика нет: `max_provider_attempts` равен 1. Повтор всей работы — новый `run` и новый ключ идемпотентности. Поле `retry_of_run_id` можно передать; на этом этапе существование предыдущего запуска в хранилище не проверяется.

## Вход `prepare_draft`

Проверка выполняется во время исполнения функцией `validatePrepareDraftInput`. Компилятор TypeScript её не заменяет. Лишние поля запрещены на каждом объекте. Возвращается первая ошибка в порядке проверок, список ошибок не собирается.

Отсутствие `destination` как ключа — ошибка формы. Черновик передаёт JSON `null`. Это предложенный способ выразить «назначения нет».

| Поле | Ограничение v0.1 |
| --- | --- |
| `schema_version` | Строка `0.1.0` |
| `workspace_id` | `^ws_[a-z0-9]{1,32}$` |
| `project_id` | `^prj_[a-z0-9]{1,32}$` |
| `operation` | `prepare_draft` |
| `mode` | `educational` |
| `topic` | Строка, обрезка пробелов по краям, 1…200 кодовых точек Unicode |
| `audience` | Строка, обрезка пробелов по краям, 1…200 кодовых точек |
| `language` | Две строчные латинские буквы, пример `ru`. Полный BCP 47 не принимается |
| `format` | `short_note` |
| `sources` | Массив, 0…10 элементов. Пустой массив проходит форму и останавливает запуск кодом `insufficient_sources`. Отсутствие ключа или не-массив — `invalid_shape` |
| `sources[].source_id` | `^src_[a-z0-9]{1,32}$`, уникален внутри входа |
| `sources[].url` | `http` или `https`, до 2000 символов, без имени пользователя и пароля в URL |
| `sources[].title` | 1…200 кодовых точек после обрезки пробелов |
| `sources[].provided_text` | 1…20000 кодовых точек. Переводы строк приводятся к `\n`. Пробелы внутри текста не обрезаются |
| `sources[].provenance.kind` | Только `fixture` |
| `sources[].provenance.fixture_id` | `^[a-z0-9][a-z0-9-]{0,63}$` и ключ каталога |
| `sources[].provenance.note` | Можно опустить или передать `null`. Иначе строка до 500 кодовых точек |
| `criteria.max_body_chars` | Целое число 1…20000 |
| `criteria.link_policy` | `sources_separate` |
| `criteria.factual_claims` | `each_bound_to_fragment` |
| `criteria.forbid_measured_savings_claims` | Булево |
| `destination` | `null` либо объект `{ channel, target, metadata_only: true }`. Иное `metadata_only` отклоняется |
| `budget.amount` | Десятичная строка `^(0|[1-9][0-9]{0,8})(\.[0-9]{1,2})?$`. Число JSON не принимается |
| `budget.currency` | `^[A-Z]{3}$`. Справочник ISO 4217 не подключён, обмен валют не выполняется |
| `budget.external_spend_amount` | Та же десятичная форма и значение 0 в учебном режиме |
| `idempotency_key` | 8…128 символов: `^[A-Za-z0-9][A-Za-z0-9_.:-]{7,127}$` |
| `retry_of_run_id` | Можно опустить: в снимке будет `null`. Либо `null`, либо `^run_[a-f0-9]{32}$` |

Каталог fixture задан в коде, не во входе:

| `fixture_id` | Файл |
| --- | --- |
| `readme-bos-pro-9b46b60` | `fixtures/readme-bos-pro.md` |
| `readme-bos-pro-injection-9b46b60` | `fixtures/readme-bos-pro-injection.md` |

`readme-bos-pro.md` — снимок `README.md` на коммите `9b46b60`, сделанный до правок README этой ветки. Текст во входе должен совпасть с файлом каталога после приведения переводов строк к `\n`. Путь из JSON не читается. Неизвестный `fixture_id` даёт `unknown_fixture`. Расхождение текста даёт `fixture_mismatch`. Оба кода отклоняют вход до создания запуска.

Область идемпотентности: `workspace_id` + `operation` + `idempotency_key`. Сравнение входа — SHA-256 канонического JSON: ключи объектов сортируются, строки кодируются UTF-8. Одинаковый ключ и тот же канонический вход возвращают тот же `run`. Другой вход с тем же ключом даёт `idempotency_conflict` и не создаёт второй запуск.

`workspace_id` и `project_id` проверяются по форме. Серверная проверка membership текущего пользователя отсутствует.

## Учебный пример

Исполняемый файл: `fixtures/educational-input.json`.

- Тема: «Как проверять результат выполнения задачи».
- Аудитория: небольшая команда. Язык: `ru`. Формат: `short_note`.
- Источник: снимок README с URL `https://github.com/dimitry8st-prog/BOS-Pro_30.10.2026/blob/9b46b603d9304e331ab51bf9f7fdecc4bc11ea19/README.md` и пометкой fixture.
- Критерии: до 600 кодовых точек основного текста; источники отдельно; без обещания измеренной экономии; каждое фактическое утверждение связано с фрагментом источника.
- Назначение: `null`. Внешний бюджет: сумма `0`, внешний расход `0`, валюта `RUB`.
- Ключ: `edu-prepare-draft-001`.

Учебный URL не запрашивается. `not_checked` не означает, что адрес доступен.

## Выход запуска

Сохранённый `RunRecord` содержит:

- `run_id`, `status`, `stop` (`null` либо `{ code, message }`);
- `artifact_id`, `current_revision`, текст и `content_hash` в отдельной версии артефакта;
- `claim_links`: утверждение → `source_id` → фрагмент, плюс `bound` и `weak`;
- `verification` со статусом, основаниями, ограничениями и списком реально выполненных проверок;
- `url_checks`: для каждого источника `status`, `checked_at` и ограничение. В учебном режиме статус `not_checked`, `checked_at` равен `null`;
- `scenario_version` `prepare_draft/0.1.0`, `rules_version` `draft_checks/0.1.0`, `workflow_version` `prepare_draft_educational/0.1.0`;
- `snapshot_ref` на неизменяемый входной снимок;
- журнал шагов;
- затраты: внешние `estimate`, `reserved`, `actual` по отдельности и модельные слоты отдельно;
- `publication.status` = `not_published`, `publication.handler` = `absent`, `publication.permitted` = `false`;
- `next_user_action`;
- `fixture: true`, `provider_name: "FixtureProvider"`;
- `test_scope`: fixture-поставщик да, реальная модель нет, живой сайт нет, RLS нет, production нет;
- `access_check: "not_performed"`.

Хеш содержимого — `sha256:` и SHA-256 точных байт UTF-8 основного текста. В хеш не входят время и метаданные. Одинаковый текст не создаёт новую версию (`revision_unchanged`). Другой текст создаёт следующую версию новым файлом; предыдущий файл не переписывается.

## Затраты

В учебном режиме внешний расход известен и равен нулю. В отчёте внешние оценка, резерв и факт записываются как `{ "amount": "0.00", "currency": "<валюта входа>" }`. Это известный ноль режима, а не подстановка вместо неизвестного.

Стоимость модели не измерялась: `estimate`, `reserved` и `actual` равны `null`, статус `not_measured`. Ноль туда не записывается.

## Статусы запуска

Переходы этого сценария:

- `queued` → `running` | `failed` | `cancelled`
- `running` → `succeeded` | `failed` | `cancelled`

`waiting_approval` есть в типе и не назначается. Переход `running` → `waiting_approval` запрещён.

Терминальные статусы `succeeded`, `failed`, `cancelled` не сменяются повторным запросом. Идемпотентный повтор возвращает уже сохранённый запуск. Новая версия текста меняет `current_revision` и текущий отчёт проверки, статус `succeeded` сохраняется, старый файл версии остаётся.

`succeeded` значит: результат и отчёт записаны в локальное хранилище. Текст может быть при этом не одобрен (`verification` не `pass`). Публикация при `succeeded` не выполняется.

Остановка:

- пустые или непригодные источники после принятой формы — `failed` / `insufficient_sources`, снимок входа сохраняется;
- отказ `FixtureProvider` — `failed` / `provider_refused`, снимок сохраняется, автоматического повтора нет;
- ошибка записи версии — `failed` / `storage_error`, если статус удалось записать. Текст исключения хранилища в журнал не копируется;
- отмена между шагами — `cancelled` / `cancelled_by_user`;
- процесс остановился в `queued` или `running` — команда `recover` переводит запуск в `failed` / `interrupted`, а если уже стоял `cancel_requested`, в `cancelled`. В `running` такой запуск не остаётся. Повторное восстановление терминальный запуск не трогает.

Восстановление срабатывает, если аренда отсутствует, помечена `abandoned` или pid аренды уже не жив. Живой pid без `abandoned` не переписывается.

## Проверки черновика

Правила `draft_checks/0.1.0` всегда исполняют пять проверок и пишут `executed: true`:

| Код | Условие pass |
| --- | --- |
| `body_length` | Число кодовых точек текста не больше `max_body_chars`. В `detail` есть фактическая длина |
| `sources_separate` | Отдельный список источников результата совпадает с источниками входа |
| `source_url_syntax` | URL входа и результата синтаксически `http(s)`. Сеть не вызывается |
| `claim_fragment_binding` | Есть хотя бы одно утверждение, и каждый фрагмент буквально входит в `provided_text` указанного источника |
| `measured_savings` | При включённом запрете в тексте и утверждениях нет шаблона измеренной экономии или числа с `%` |

Статус отчёта: `fail`, если хотя бы одна проверка не прошла; иначе `needs_review`, если связанный фрагмент короче 12 кодовых точек; иначе `pass`. Порог 12 — предложение, не измеренный критерий качества.

Ограничение про ссылки входит в отчёт всегда: доступность адреса не является доказательством истинности утверждения. Даже статус `reachable` описывал бы только ответ адреса. Учебный прогон этот статус не ставит.

`quality_gate` равен `open` только при `verification.status = pass`. `publication.permitted` на этом этапе всё равно `false`.

## Хранилище

`DevStore` пишет каталог с файлом `DEV_ONLY_STORAGE.json`. Класс хранилища: `development-only`. `durable_production_storage`: false. `process_memory`: false.

Файлы запуска, снимка, версий и ключа идемпотентности читаются новым процессом. Это локальный диск учебной машины. Память процесса хранилищем не называется. Общий сервер поверх этого каталога не создаётся.

Журнал хранит `run_id`, шаг, время, исход, безопасный код ошибки, версии схемы и правил, ссылки на артефакты и затраты. Полный текст источника и секреты в журнал не кладутся. Снимок входа хранит переданный текст отдельно: для учебного fixture это и есть данные задания.

## Доверие

Читаются только файлы каталога внутри `fixtures/`. Совпадение пути проверяется после `realpath`. Команды из текста источника не исполняются. Сеть моделью и проверкой URL не вызывается.

Остановка исполнения: отмена; нарушение контракта; отсутствие источников; отказ поставщика; ошибка хранилища. Внешних побочных действий у этапа нет. Откат — возврат ветки; диагностические файлы локального каталога можно сохранить или удалить вместе с `var/`.

## Неоднозначности

Закрыты только как предложение этого файла:

1. Символ лимита — кодовая точка Unicode, не графемный кластер и не единица UTF-16.
2. Деньги — десятичные строки, не числа JSON.
3. Отсутствие назначения — JSON `null`, пропуск ключа отклонён.
4. Идентификаторы имеют префиксы `ws_`, `prj_`, `src_`, `run_`, `art_`.
5. Язык на этом шаге — две строчные буквы.
6. Пустой список источников создаёт неуспешный запуск; пропуск поля отклоняется раньше.
7. Валидатор возвращает одну первую ошибку.
8. `needs_review` назначается слабому фрагменту короче 12 кодовых точек. Других источников `needs_review` правила не дают.
9. Ручная правка переносит прежние связи с фрагментами и заново гоняет проверки. Новые утверждения из свободного текста сами не извлекаются.
10. `retry_of_run_id` записывается и не сверяется с другим запуском.
11. Валюта проверяется как три заглавные буквы, не как реестр ISO.
12. Известный нулевой внешний расход и неизвестная стоимость модели записываются по-разному.
13. Терминальный статус неизменяем; новая версия текста добавляет файл, а не переписывает старый.

Остаются открытыми и этим этапом не решаются:

- первый реальный набор источников и канал назначения;
- разрешённый модельный endpoint, бюджет на запуск и на период;
- размещение приложения и данных, параметры среды;
- один пользователь или совместная работа, роли;
- лицензия и срок хранения реальных пользовательских данных;
- миграции PostgreSQL, RLS и проверка membership;
- живая проверка URL и правило, что делать при таймауте будущей публикации.

Учебные данные лежат локально, пока идёт приёмка. Политика реальных данных не выбрана.

## Что прогон не доказывает

Тест `FixtureProvider` проверяет управление выполнением на фиксированных данных. Он не является тестом реальной модели, живого сайта, RLS или production. Аутентификация и изоляция workspace должны быть реализованы и проверены до совместного использования. Текущий прототип этого не подтверждает.
