# Модель данных BOS.pro

Статус: единый черновой контракт. Готовой SQL-миграции в пакете нет.

## Основные сущности

| Сущность | Назначение | Главная связь |
| --- | --- | --- |
| workspace | Область данных команды или владельца | Корень клиентских данных |
| workspace_membership | Участник и его роль | Пользователь → workspace |
| project | Проект с целями и ограничениями | workspace → project |
| task | Конкретное задание и критерии результата | project → task |
| campaign | Маркетинговая кампания | project → campaign |
| experiment | Проверяемая гипотеза кампании | campaign → experiment |
| workflow_version | Неизменяемая версия сценария | Версия шагов, входов и правил |
| run | Конкретный запуск задания | task + workflow_version → run |
| run_step | Шаг запуска и его состояние | run → run_step |
| artifact | Версия текста, файла или другого результата | run → artifact |
| verification | Проверка конкретной версии результата | artifact → verification |
| approval | Разрешение конкретного действия | artifact revision + destination + action |
| metric_event | Исходное измерение с происхождением | campaign/experiment + период/время |
| audit_event | Кто и что сделал | workspace + сущность + время |

Кампания и эксперимент не обязательны для обычной задачи подготовки текста.
Если они используются, эксперимент принадлежит кампании; связь с проектом
выводится через campaign, а не задаётся вторым независимым родителем.

## Изоляция данных

Клиентские сущности содержат workspace_id. Составные внешние ключи или эквивалентные
ограничения гарантируют, что родитель принадлежит тому же workspace. Сервер
проверяет участие и роль пользователя. RLS ограничивает операции соответствующими
строками, а SQL grants — сами доступные операции. Service-role ключ остаётся серверным.
Нужны отдельные проверки запрета чтения, изменения и переноса данных между workspace.

## Состояния запуска

`queued`, `running`, `waiting_approval`, `succeeded`, `failed`, `cancelled`.
Для каждого перехода определяются разрешённый инициатор и условия. Завершённый
запуск не переписывается повторным запросом. Повторная работа создаёт новый run
со ссылкой на предыдущий. Идемпотентный повтор запроса создания возвращает исходный run.

## Метрики и стоимость

Хранятся исходные spend, clicks, impressions, conversions, валюта, период,
источник и правило атрибуции. Счётчики неотрицательны и конечны. При conversions=0
CPA отсутствует (`null`, статус `not_available`), расходы при этом сохраняются.
При conversions>0 CPA = spend / conversions. Смешение валют и окон атрибуции
без явного преобразования запрещено.

budget / targetCPA — плановый сценарий при заданной целевой стоимости, а не прогноз
реальных конверсий. Стоимость ИИ-запуска учитывается отдельно от рекламных расходов.
Оценка стоимости, зарезервированный лимит и фактическая стоимость различаются.

## Граф и результаты

Типы узлов задаются явно: trigger, action, condition; action выбирается из серверного
реестра разрешённых действий. Граф имеет версию схемы, проверку ссылок, границы
повторов и лимит шагов. Модель не может добавить произвольный обработчик.

Результат сохраняется с хешем содержимого, версией сценария и ссылками на входы.
Подтверждение устаревает при изменении результата или назначения действия.
